View transitions

Five CSS techniques. Click everything. Each section is cited by the skill's reference files.

1. Card becomes a page

One property. Both sides carry view-transition-name: hero, so the browser morphs the thumbnail into the hero slot instead of cutting.

2. Rows travel to a new position

Each row takes its own name via --trip. Sort, then hide visited.

    Both rows above now share --trip: clash. They will not animate — and nothing throws. This is the most common “it just doesn’t animate” cause, and in plain CSS it is completely silent.

    3. Theme toggle that spreads from the click

    A clip-path reveal on ::view-transition-new(root), with the click point fed in as --x/--y.

    4. Modal born from the button that opened it

    The button holds view-transition-name: share. Inside the transition it must relinquish that name to the dialog. Skip the rename and the dialog appears from nowhere — there is no continuity to trace back to.

    The button kept its share name and the dialog never took it, so there was nothing to hand over. The dialog just appeared — no continuity back to the button. Compare with the button above.
